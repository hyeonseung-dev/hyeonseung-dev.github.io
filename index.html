결제 이후 후속 작업의 실패 경계 분리

Coffee Order System

주문·포인트·인기 메뉴 API를 구현한 뒤 동시성, 인덱스, MySQL 읽기/쓰기 분리, Redis 장애 복구를 단계적으로 검증한 1인 백엔드 프로젝트입니다.

STACKSpring Boot · JPA · MySQL · Redis

핵심 문제 해결

동시 주문 Lost Update 방지

10,000포인트 사용자가 3,000포인트 주문을 동시에 10건 요청하도록 재현하고 비관적 락을 적용해 3건 성공·7건 실패·최종 잔액 1,000P로 정합성을 검증했습니다.

복합 인덱스로 인기 메뉴 집계 63.1% 개선

주문 50만 건 환경에서 여러 인덱스 후보를 비교해 179ms → 66ms로 단축하고 (menu_id, ordered_at, status) 인덱스를 선택했습니다.

Primary / Replica 읽기·쓰기 분리

readOnly 트랜잭션은 Replica로, 주문·포인트 차감·락은 Primary로 라우팅하고 실제 요청이 의도한 DB로 전달되는지 검증했습니다.

Redis 장애에도 서비스 유지

Sentinel 3대를 구성해 Master 자동 승격을 확인하고, Redis 전체 장애 시 MySQL fallback으로 핵심 API가 계속 동작하는지 확인했습니다.

핵심 문제 해결

JWT 로그아웃·재발급 정책 설계

로그아웃한 Access Token은 남은 만료 시간 동안 Redis Blacklist로 차단하고, Refresh Token은 저장값 일치 시에만 교체하는 Rotation을 적용했습니다.

S3 Presigned URL로 이미지 업로드 경로 분리

이미지 바이트가 애플리케이션 서버를 거치지 않도록 클라이언트가 S3에 직접 업로드하게 하고 DB에는 imageKey만 저장했습니다.

GitHub Actions와 AWS로 CI/CD 자동화

테스트·빌드·Docker 이미지 생성·ECR Push·EC2 배포를 하나의 흐름으로 연결하고 OIDC 기반 임시 권한과 배포 후 Health Check·Rollback을 적용했습니다.
